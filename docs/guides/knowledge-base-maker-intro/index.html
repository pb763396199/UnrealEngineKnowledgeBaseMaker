为什么需要它

Agent 卡的不是写代码，是读不懂代码库

grep 满屏噪声 → 分不清 声明/实现/调用 → 几十万行塞不进上下文
缺的不是算力，是 UE 语义化的索引地图。
产出流水线 · 一条 ue5kb init
1discover扫 .Build.cs
2extract依赖/类/函数
3analyze继承/调用图
4buildSQLite 索引
5generate生成 Skill
preflight查询前预检，stale 自动刷新
query_class_info继承链/模块/行号/说明符
get_function_impl直接返回完整实现代码
ensure_fresh按 worktree 对齐快照
和裸 grep 的差异
  • UE 语义化：继承链/依赖/UCLASS 说明符，不止文本匹配
  • 渐进披露：摘要→详情→源码，80–85% 上下文压缩
  • 索引快查：类 500x / 函数 800x，毫秒级返回
  • 带新鲜度：结果标注 fresh/stale，杜绝幻觉
+ 多分支快照：DEV / DEV_1 / DEV_2 并存，去重不占空间
读得准 · UE 语义索引 查得快 · 毫秒级返回 多分支可信 · 每分支独立快照
